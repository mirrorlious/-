## 1. 用户原始要求

当前分栏阅读界面左右仍有较大留白，希望默认占据整个浏览器可用宽度；正文可提供两栏排版，从而形成“文章两栏 + 学习侧栏”；右侧全文结构、精读结果和学习笔记应随页面滚动保持可见，并在侧栏内部独立滚动；正文顶部按钮统一靠右，尽量使用图标而不是文字按钮。

## 2. 本次范围

- 阅读模式与 PDF 模式取消外层最大宽度和左右空白，主界面默认铺满可用宽度。
- 阅读工具栏统一右对齐。
- 纯净/精读、标准/分栏/专注、文章单/双栏、侧栏、全屏、沉浸和全文工具改为图标按钮，并保留 `title` 与 `aria-label`。
- 新增文章单栏/双栏切换，宽屏默认双栏并保存本地偏好。
- 双栏正文使用报刊式顺序排版，段落尽量避免跨栏断开。
- 右侧学习侧栏改为视口内 sticky 容器，标签栏固定，内容区域独立滚动。
- 保留段落 `⋯` 菜单、选区工具、批注、PDF/OCR、结构树编辑和现有模型调用。

## 3. 明确不做

- 不修改选区工具条分级。
- 不改 OCR、PDF 提取、API 路由、缓存或 Firebase。
- 不增加新的模型任务。
- 不合并到 `main`。
- 不读取或修改 Miki 工程及仓库中的其他无关历史文件。

## 4. 当前问题定位

- 顶层 `<main>` 在分栏模式仍受 `max-w-[1480px]` 限制，大屏两侧形成明显空白。
- 正文工具栏由多个文字按钮组组成，阅读模式、布局模式和全文操作混在一起，视觉密度过高。
- 正文段落容器受 `--reader-measure` 限制，无法利用宽屏形成报刊双栏。
- 侧栏虽有 `position: sticky`，但由侧栏外层整体滚动，标签栏与内容没有稳定分层，长内容体验不够明确。
- 一次性实施工作流已登记；本提交用于在工作流存在后触发执行。

## 5. 实施计划

1. 增加 `articleColumnMode` 状态并写入 `layoutState`。
2. 扩展 CSS：全宽工作区、双栏正文、段落防断栏、固定高度 sticky 侧栏及内部滚动。
3. 重写正文顶部工具栏为右对齐图标组。
4. 调整阅读模式与 PDF 模式的 header/main 宽度和正文内边距。
5. 调整右侧面板结构类名，使标签栏固定、内容独立滚动。
6. 执行静态标记、`git diff --check` 和 Babel JSX 解析；成功后删除一次性脚本与工作流。

## 6. 验收标准

- 1920px 等大屏下阅读区域贴近浏览器两侧，不再出现成片无意义留白。
- 所有正文工具集中在工具栏右侧，主要操作使用图标，悬停可查看文字说明。
- 标准、分栏、专注三个图标易于区分，选中态清楚。
- 宽屏可切换文章单栏/双栏，刷新后保持偏好。
- 双栏时段落不被轻易拆成上下两截，阅读顺序为先左栏后右栏。
- 右侧标签栏持续可见，导图、精读结果和笔记在侧栏内部滚动。
- 页面滚动时右侧面板保持在顶栏下方。
- 原有段落菜单、批注和全文工具继续可用。
- Babel JSX 解析通过。
