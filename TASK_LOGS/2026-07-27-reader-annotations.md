# 任务：句子级批注与 Notes 面板升级

- 时间：2026-07-27
- 执行者：ChatGPT

- 基线分支：`feat/reader-layout-context-typography`

- GitHub：用户已明确授权直接修改远程分支

## 1. 用户原始要求

在已完成的左右分栏阅读页基础上，把右侧 Notes 从单一全文记事框升级为类似 Word 的原文批注：用户选择一句或一段文字后可以添加批注；右键可作为快捷入口；批注与原文位置绑定；点击批注可回到原文。

## 2. 本次范围

- 选区工具条增加“批注”入口
- 正文选区右键快捷菜单
- `Ctrl/Command + Alt/Option + M` 快捷键
- 句子批注数据结构与本地持久化
- Notes 内拆分“批注 / 全文笔记”
- 批注卡片、编辑、删除、跳回原文
- 原文批注高亮
- 中文化当前阅读布局及右侧面板标签
- 与生词高亮、选区翻译和现有 AI 操作兼容

## 3. 明确不做

- 不修改 API、OCR、PDF、计费和模型路由
- 不新增云端批注同步
- 不修改 Firebase 数据结构
- 不引入第三方编辑器或字体依赖
- 不直接合并到 `main`

## 4. 审计结果

- 真实源码为根目录单文件 `index.html`，React + Babel CDN。
- `Paragraph` 已实现段落内选区检测、复制、翻译和朗读，但没有稳定位置锚点或批注入口。
- 右侧 `notes` 当前只是无状态 textarea，没有保存逻辑。
- 正文由 `paragraphs.map` 渲染，段落索引可作为稳定的第一层锚点。
- 已有本地状态统一保存到 `yang-reader-state-v1`，适合增加版本化 `readingNotes`。
- 生词高亮通过 React 分段渲染，禁止使用 `innerHTML.replace` 注入批注。

## 5. 实施计划

1. 增加文章级 notes 状态和迁移安全的持久化结构。
2. Paragraph 向 App 上报选区锚点与批注请求。
3. 为批注建立 paragraphId、offset、exact、prefix、suffix 锚点。
4. Notes 面板拆分“批注”和“全文笔记”。
5. 在现有 React 文本片段渲染中组合批注区间，不破坏生词高亮节点。
6. 增加右键和键盘快捷入口。
7. 中文化本次涉及的原型英文标签。
8. 通过静态语法检查、差异检查和浏览器级手工验收清单验证。

## 6. 风险

- 单文件源码较大，补丁必须使用精确锚点并在失败时停止。
- 批注范围可能与生词 span 重叠，必须统一按文本偏移切片。
- 文章文本修改后锚点可能失效，需要 exact/prefix/suffix 作为未来恢复依据。
- 当前任务只保存到本机浏览器，不承诺跨设备同步。
- 第一版选区批注限定在同一段落内；跨段选区不会拦截浏览器原生行为。

## 7. 验收标准

- 选中文字可通过工具条、右键和快捷键添加批注。
- 保存后右侧出现批注卡片，刷新后仍存在。
- 原文出现不改变行高的批注标记。
- 点击卡片滚动并高亮对应原文。
- 可编辑和删除批注。
- 全文笔记独立保存。
- 无选区时不拦截浏览器右键。
- 原有复制、翻译、朗读、生词点击和段落功能不受影响。

## 10. 数据结构

`readingNotes.version = 1`，按 `currentHistoryId` 保存：

- `documentNote`：全文笔记
- `annotations[]`：`id`、`anchor`、`note`、`createdAt`、`updatedAt`
- `anchor`：`paragraphIndex`、`startOffset`、`endOffset`、`exact`、`prefix`、`suffix`

批注默认只保存到现有 `localStorage` 状态，不同步 Firebase。
