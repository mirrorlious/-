## 1. 用户原始要求

当学习侧栏没有拉起时，“翻译本段”和“长难句讲解”应直接显示在相应段落下方。该行为主要服务手机端，避免用户每分析一段都必须滚动到文章末尾查看结果。

## 2. 任务目标

- 桌面宽屏且学习侧栏真实停靠在正文右侧时，段落翻译与长难句继续进入右侧“精读结果”。
- 学习侧栏关闭时，段落翻译与长难句显示在原段落下方。
- 小于 1200px 的单列/移动布局中，即使保留学习侧栏入口，段落翻译与长难句仍优先在原段落下方显示，不再路由到文章末尾的侧栏区域。
- 视口从宽屏缩小到移动尺寸时，已展开的段落结果应自动回到段落下方，无需重新生成。

## 3. 本次范围

- `index.html` 中学习侧栏是否“真实停靠”的响应式判断。
- `Paragraph` 的 `inlineResultsEnabled` 传值。
- 段落结果进入右侧面板的路由条件。

## 4. 明确不做

- 不修改全文翻译、全文逻辑、结构树、模拟习题和学习笔记的侧栏行为。
- 不修改模型调用、缓存结构、IndexedDB、Markdown 备份或 PDF/OCR。
- 不修改视觉系统或重构段落组件。
- 不修改或合并到 `main`。

## 5. 审计结果

- 段落组件已有 `inlineResultsEnabled`：为真时，翻译和 `SyntaxBreakdowns` 会渲染在段落下方。
- 修改前父组件仅依据 `layoutMode === 'split' && rightPanelOpen` 判断是否禁用段落内联结果。
- CSS 在小于 1200px 时将 `.reader-workspace-split` 改为单列，并把 `.reader-side-panel` 放回普通文档流；此时侧栏位于全文末尾，但状态仍可能是 `rightPanelOpen === true`。
- 因此移动端会错误地禁用段落内联结果，并把段落结果路由到文章末尾的学习面板。
- 正确判定应同时考虑视口是否达到 1200px，即只有“宽屏 + 分栏 + 侧栏开启”才把段落结果送入右侧面板。

## 7. 实施计划

1. 增加基于 `matchMedia('(min-width: 1200px)')` 的响应式状态。
2. 定义 `isLearningPanelDocked`，表示学习侧栏是否真实以双栏方式停靠。
3. 使用 `!isLearningPanelDocked` 控制段落翻译和长难句的内联展示。
4. 仅在 `isLearningPanelDocked` 为真时，把段落结果路由到右侧学习面板。
5. 运行静态标记检查、`git diff --check` 和 Babel JSX 解析。
6. 删除一次性脚本与工作流，提交功能修改。

## 8. 实际修改

- 新增 `isLearningPanelWide`，通过 `matchMedia('(min-width: 1200px)')` 与现有 CSS 断点保持同步。
- 新增 `isLearningPanelDocked`：只有宽屏、分栏布局并且侧栏开启时才视为真正的右侧停靠面板。
- `Paragraph.inlineResultsEnabled` 改为 `!isLearningPanelDocked`。
- 段落结果只在 `isLearningPanelDocked` 为真时进入右侧学习面板。
- 侧栏关闭、标准/专注布局或小于 1200px 时，段落翻译与完整长难句拆解直接显示在对应段落下方。
- 视口尺寸变化会实时更新；从桌面缩小到手机尺寸时，已展开结果会自动回到段落下方。
- 全文级结构、练习、笔记和全文分析的侧栏行为未修改。
