### 2. 真正服务阅读的分栏

- **正文单栏 / 双栏**：宽屏下可采用报刊式双栏顺序阅读。
- **标准 / 分栏 / 专注**：按任务切换阅读空间。
- **学习侧栏 sticky 跟随**：正文下滑时，侧栏持续停留在视口内，并在内部独立滚动。
- **全宽布局与图标工具栏**：减少页面两侧无效留白，工具集中到正文右上方。
- **关闭侧栏后自动回退**：段落翻译和长难句结果重新显示在原段落下方。

## 🧩 学习侧栏

右侧固定为四个稳定入口：

| 标签 | 用途 |
|---|---|
| **全文结构** | 在纵向结构树与思维导图之间切换；两种视图共用同一份数据 |
| **模拟习题** | 全文三题和段落单题集中作答，提交后才显示答案与解析 |
| **精读结果** | 堆积多个段落翻译，显示长难句拆解与全文逻辑 |
| **学习笔记** | 管理选区笔记、颜色、定位、编辑、删除与全文笔记 |

### 结构树与思维导图

- 中英双语节点；
- 分支展开 / 收起；
- 结构树与导图一键切换；
- 全屏缩放；
- 双语标题编辑；
- 新增、删除子节点；
- 保存到当前文章历史。

### 段落翻译堆积

连续点击多个段落的“翻译本段”时，结果不会互相替换：

```text
第 3 段译文
第 7 段译文
第 11 段译文
```

同一段再次打开会更新原卡片，并支持逐条移除或全部清空。

每个长难句还会包含：

- 🤖 AI 模拟例句；
- 📚 真题语料库相似原句、年份和来源；

## 📝 笔记与批注

选中部分文字即可添加笔记，不必只能记录全文笔记。

## 🎯 模拟习题

### 全文练习

固定生成 **3 道考研英语风格选择题**：

1. 全文主旨或作者观点；
2. 重要细节、推断或逻辑关系；
3. 语境词义、作者态度或写作目的。

用户完成三题并提交后，系统才显示：

- 总得分；
- 正误状态；
- 正确答案；
- 中文选项；
- 逐题解析。

### 段落练习

段落单题同样采用：

```text
选择答案 → 提交 → 显示正误与解析
```

题目统一进入 **模拟习题**，不再占用精读结果区域。

## 📚 PDF、图片与整本书

### 本地原样阅读

PDF 可直接在浏览器中分页、缩放、适宽和下载：

- 不上传文件；
- 默认不提取文字；
- 适合先确认版面与清晰度。

### 智能识别与拆分

对于大型 PDF：

1. 优先读取 PDF 文字层；
2. 低文本页才调用 OCR；
3. 按页缓存进度；
4. 过滤封面、目录、页码和低信息页；
5. 根据标题、分栏和自然段切分文章；
6. 预览后保存单篇或批量加入阅读库。

> [!WARNING]
> 复杂杂志版式仍可能需要人工调整文章边界。受版权保护的 PDF、书籍和完整期刊内容不应提交到公开仓库。

## 💾 可携带 Markdown 学习档案

浏览器缓存并不是永久保险，因此每篇文章都可以下载为完整 `.md` 文件。

### 文件里保存什么

- 文章标题与英文原文；
- 全文翻译、全文逻辑；
- 结构树与思维导图；
- 全文练习与段落练习；
- 段落翻译和长难句解析；
- 选区笔记与全文笔记；
- 内容哈希、模型信息和更新时间。

### 文件里不会保存什么

- API Key；
- Authorization 信息；
- 音频 URL 或音频 Blob；
- 浏览器临时界面状态。

Markdown 上半部分可直接阅读，末尾附带机器恢复数据块：

````md
```yang-reader-data
Base64 编码的完整文章数据包
```
````

重新上传后，可以恢复文章、解析、导图、题目和笔记。

## ⚙️ 阅读库与批量全文解析

阅读库支持批量选择文章，并建立串行分析队列。

```mermaid
flowchart LR
    A[阅读库多选] --> B{选择模块}
    B --> C[全文翻译]
    B --> D[全文逻辑]
    B --> E[结构树 / 思维导图]
    B --> F[全文三题]
    C --> G[逐模块写入 IndexedDB]
    D --> G
    E --> G
    F --> G
    G --> H[批量导出 Markdown]
```

队列特性：

- 默认每次处理一篇文章；
- 已有结果自动跳过；
- 每个模块完成后立即落盘；
- 单篇失败不会阻塞整个任务；
- 支持暂停、继续、取消和失败原因；
- 支持把所选文章导出为一个可重新导入的 Markdown 文件。

## 🔐 BYOK 与本地数据边界

> [!CAUTION]
> 本项目采用 **Bring Your Own Key**。不要把 API Key 写进源码、提交记录、URL、日志或公开截图。

| 数据类型 | 默认位置 |
|---|---|
| 小型排版和界面偏好 | `localStorage` |
| API Key | `sessionStorage`；仅在用户主动选择后记住 |
| 正文、AI 结果、导图、题目、任务进度 | IndexedDB |
| 可迁移备份 | 用户下载的 Markdown |
| Firebase | 可选沙盒同步，不作为大型 AI 结果的默认存储 |

缓存基于内容哈希、模型、服务商协议、Prompt 版本和任务类型。相同输入优先读取本地结果，避免重复请求与重复计费。

## 🌐 部署到 GitHub Pages

1. 将代码推送到 GitHub；
2. 打开仓库 **Settings → Pages**；
3. 选择部署分支和根目录；
4. 保存后等待静态页面发布。

根目录已有 `index.html`，无需额外构建步骤。

<details>
<summary><strong>部署后打不开 AI 功能？</strong></summary>

<br />

请优先检查：

- 模型服务商是否允许浏览器端请求；
- Base URL 是否正确；
- API Key 是否仍在当前会话；
- 浏览器控制台是否出现 CORS、401、403、404 或 429；
- 当前任务是否路由到正确的分析 / OCR / TTS 模型。

## 已知限制

- 批量分析会消耗用户自己的模型额度；
- 关闭页面后，正在运行的 JavaScript 队列会停止，但已完成结果和任务记录会保留；
- 浏览器站点数据被清除后，本地内容可能丢失，需通过 Markdown 恢复；
- PDF 多栏、跨页标题、图片文字混排仍可能需要人工校正；
- 不同模型的 JSON 稳定性和输出质量存在差异。
